== C3, the defect ==
Two runs of offline2.mjs, same code, one variable: whether /offline was opened
in the browser while the network was up.

COLD, which is the owner's real path (install, use the five tabs, lose the
network, then open anything not already cached):
  navigate to /settings/backup with the network disabled on the page and on the
  service worker target
  document.title  "Offline · Vernier"
  what renders    "This screen failed to load /
                   Failed to load chunk /_next/static/chunks/1ekd5rmj9g-ub.js
                   from module 64893 /
                   The rest of the app is unaffected. The five tabs below still
                   work. / Try again"
  failed request  net::ERR_FAILED .../_next/static/chunks/1ekd5rmj9g-ub.js
  capture         captures/offline-cold.png

WARM, only after /offline had been opened once while online:
  what renders    "This phone cannot reach the Mac mini / The app shell is
                   stored on this device, so it opened. Everything else waits
                   for lamberts-mac-mini.tailda76d6.ts.net. Either this device
                   has left the tailnet, or the Mac mini is asleep or stopped.
                   / WHAT WORKS OFFLINE ... / Try again"
  capture         captures/offline-warm.png

Cause: public/sw.js SHELL_ASSETS precaches the /offline document but no
/_next/static entry. cache.addAll stores the HTML only, so the JS chunk that
/offline's client bundle needs is fetched lazily on a real visit and is absent
from a cache built by the install event. Offline, that chunk request fails and
the error boundary paints over the offline screen. The service worker itself is
correct: registration is active at scope /, the controller is /sw.js, and
/sw.js is served with cache-control: no-cache, no-store, must-revalidate.
